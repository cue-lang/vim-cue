## Project-specific instructions

### What this is

A Vim filetype plugin for [CUE](https://cuelang.org) (`*.cue` files): syntax
highlighting, indentation, folding, and a Syntastic checker. It is pure
Vimscript — there is **no build step, no test suite, no linter, and no package
manager**. Changes take effect simply by being on Vim's `runtimepath`.

The plugin is historically derived from `google/vim-jsonnet` (which itself
derives from Google's jsonnet). `indent/cue.vim` is a near-verbatim copy of
Vim's distributed JSON indent file (see `indent/VIM_LICENSE`), and still calls
its function `GetJSONIndent()` and checks for the `jsonString` syntax group.

### Workflow

This repo has no `codereview.cfg`, so it uses the **GitHub-PR-only** workflow
described in the common guidance above (no GerritHub, no Change-Ids, no
git-codereview tooling; review and CI happen on GitHub via `gh` and GitHub

is `cue-lang/vim-cue` (the `myitcv` remote). The default branch is `master`.

### Repository layout and Vim's load model

There is no central entry point. Vim auto-loads each file by its directory
according to `runtimepath` conventions; understanding *when* each runs is the
key to working here:

- `ftdetect/cue.vim` — maps `*.cue` to filetype `cue`. Runs at startup.
- `syntax/cue.vim` — highlighting. Runs when a `cue` buffer's syntax is enabled.
- `indent/cue.vim` — `indentexpr` logic. Runs when indenting is enabled.
- `ftplugin/cue.vim` — per-buffer settings (e.g. `commentstring`). Runs per `cue` buffer.
- `plugin/cue.vim` — global setup; defines the `vim-cue` augroup that sets
  `foldmethod=syntax` / `foldlevel=100` on `*.cue`. Runs once at startup.
- `syntax_checkers/cue/cue.vim` — optional [Syntastic](https://github.com/vim-syntastic/syntastic)
  checker; registers a `cue` checker only when Syntastic is present.
- `doc/vim-cue.txt` — `:help` documentation. `doc/tags` is generated by `:helptags`.

### Conventions

- **Syntax highlighting maps CUE onto standard Vim highlight groups**
  (`Number`, `Keyword`, `Type`, `String`, `Constant`, `Special`, `Statement`,
  etc.) rather than defining custom `cue*` groups. Follow this when extending
  `syntax/cue.vim` so user colorschemes apply without extra linking.
- **The builtin function list** in `syntax/cue.vim` (the long run of
  `syn match Constant "pkg.Func"` lines) is hand-maintained from
  `cuelang.org/go/pkg`. Update it when CUE adds/removes stdlib builtins.
- Syntax/indent rules track the CUE language version; e.g. block comments were
  removed in CUE 0.11 and the corresponding rule is commented out.

### Current branch: `lsp_aware`

This branch (commit "all: make LSP aware", marked WIP / "DO NOT SUBMIT")
**removes the plugin's own `cue fmt` integration** in favor of delegating
formatting and diagnostics to an LSP client running `cue lsp`. Specifically it
deleted `autoload/cue.vim` (`cue#Format()`), the `:CueFmt` command, and the
format-on-save autocmd / `s:fmtAutosave()`.

Consequence: `doc/vim-cue.txt` is now **stale** — it still documents `:CueFmt`,
`cue#Format()`, and the `g:cue_fmt_*` / `g:cue_command` settings, none of which
exist on this branch. Keep this in mind before citing the docs as current, and
update them when finalizing LSP-related work.

### Developing and testing changes

There is no automated harness; test manually by loading this directory and
opening a `.cue` file in a clean Vim:

```sh
vim -u NONE -N -c 'set rtp^=.' -c 'syntax on' -c 'filetype plugin indent on' some.cue
```

Useful in-editor checks:
- Highlight group under the cursor:
  `:echo synIDattr(synID(line('.'), col('.'), 1), 'name')`
- Reload syntax after editing `syntax/cue.vim`: `:syntax off | edit`
- Regenerate help tags after editing `doc/vim-cue.txt`: `:helptags doc/`
